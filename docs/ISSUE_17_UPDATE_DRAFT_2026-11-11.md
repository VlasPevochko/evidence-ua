## Три найближчі результати

1. **Маршрут плеча.** Атлас → будова й функція → рух → дві наявні вправи → читання доказів → джерела. Входи з головної й Атласу, повернення з бібліотеки, правильні прямі посилання, мобільна й клавіатурна перевірка. Локальна реалізація проходить 136/136 тестів і окрему браузерну перевірку на 360/390/1440 px. Загальний Browser QA ще має дві помилки Canvas-пікселів, відтворені на незміненому main; потрібен їх розбір і 5 реальних телефонних сесій.
2. **Науковий перегляд.** Для обох вправ і кожного застереження #119 зафіксувати точне твердження, джерело, популяцію, результат, обмеження й потрібне рішення рецензента. Відео-, редакційний і науковий статуси окремі. Змінювати Claims, зв'язки та впевненість лише після зафіксованого погодження.
3. **Перевірене вимірювання.** Узгодити три дії: старт маршруту, відкриття вправи, відкриття джерела. Спочатку локальний отримувач, контрольовані ID й відсутність зайвих подій; зовнішній збір лише після погодження провайдера, коду, даних і згоди. Без атрибуції до старту звітувати окремі лічильники, не конверсію людей.

## Що ще не можна закрити

- Поточний [DEPLOYMENT.md](https://github.com/VlasPevochko/evidence-ua/blob/b2fe447886a0ca551161c6f1956caceaf6606ce7/docs/DEPLOYMENT.md) називає GitHub Pages основним сайтом. [site-publish.yml](https://github.com/VlasPevochko/evidence-ua/blob/b2fe447886a0ca551161c6f1956caceaf6606ce7/.github/workflows/site-publish.yml) містить перевірку main та умовне розгортання Pages. У цьому аудиті не підтверджено фактичний deployment саме b2fe447: порожня відповідь API статусів не є доказом успішного CI.
- Для старих Stage C пунктів є позитивне технічне підтвердження: `tests/pubmed.test.mjs` проходить мережеві/HTTP/JSON/тайм-аут помилки й API-помилки при HTTP 200; `tests/evidence.test.mjs` проходить 30 перевірок, зокрема унікальні ID карток джерел для всіх Claims у сторінці й drawer. Це локальна перевірка на поточній базі, не доказ проходження CI саме майбутнього PR.
- Публічні подання авторів, модерація й персоналізація залишаються поза поточним результатом.
- Коліно — наступна перевірка повторного використання після валідації плеча.

Issue #17 слід залишити відкритим до виконання визначення готовності поточної фази або його явного перегляду власником.

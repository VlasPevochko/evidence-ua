# Evidence UA: виправлення після оцінки

## Доручення та мета

Власник доручив скорегувати сайт після оцінки. Виправляємо підтверджені помилки й перешкоди для першого знайомства, зберігаючи наявні модулі та оформлення.

## Узгоджений обсяг

- Відсутні або нечислові межі довірчого інтервалу не стають нулями. Справжні числові нульові межі зберігаються.
- Каталог не суперечить попереднім оцінкам у досьє: детальний статус залишається біля конкретного твердження.
- Картка «Від їжі до клітини / Травлення та всмоктування» відкриває `nutrition-digestion.html`.
- Три наявні навчальні маршрути на головній видно одразу: переносимо чинний блок за межі «Про сайт», залишаємо його відкритим за замовчуванням і зберігаємо його ID, посилання та можливість згортання.
- «Напрями» веде в єдиний каталог; прибираємо дубль «Каталог» з основної шапки, зберігаємо решту тематичних переходів.
- Пошук закривається при виборі результату, включно з переходом у межах того самого документа.
- Усуваємо відому залежність негативного тесту синтаксису від автоматичного визначення типу `.js` у Node 24.19: тестовий сайт має той самий явний `type: module`, що й справжній.

## Підхід і межі

Обрано локальні зміни чинних компонентів, native HTML details і наявних CSS. Повна перебудова навігації або дизайну не потрібна для цих дефектів. Нових бібліотек немає.

Claims, Sources, Evidence Records, дати наукового перегляду та погоджені рівні впевненості не змінюємо. Незалежні історичні science-digest fixtures не перераховуємо: у порівнянні допускаємо лише чітко окреслену технічну зміну чотирьох відсутніх інтервалів, як уже нормалізується історичний рівень заголовків.

Резервна копія: `/workspace/scratch/evidence-ua-before-corrections-9c20f03.tar.gz`. Робота в наявній ізольованій хмарній машині, окрема гілка; новий Git worktree не створюємо. Після перевірок — коміт і PR. Merge лише після явного рішення власника. Пряме розгортання в обхід PR не виконуємо.

## Перевірка

Спершу регресії відтворюють помилки, потім мінімальні виправлення. Після інтеграції — `npm run check`, перевірка повторюваності збірки та незалежний перегляд diff. Browser QA і live-перевірка залежать від наявного підтримуваного браузера та мережевого доступу; їхній незапущений стан повідомляємо окремо.
